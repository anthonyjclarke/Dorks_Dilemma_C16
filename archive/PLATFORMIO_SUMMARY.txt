================================================================================
BUILD SYSTEM OPTIONS
================================================================================

Method 1: PlatformIO (Recommended)
-----------------------------------
Commands:
  pio run                    # Build
  pio run -t clean          # Clean
  pio run -t upload         # Run in emulator

Integration:
  • VSCode native integration
  • Full IDE features
  • Custom 6502 build script
  • Automatic tool management

Method 2: Makefile (Fast)
-------------------------
Commands:
  make                      # Build
  make clean               # Clean
  make run                 # Build and run
  make debug               # Run with monitor
  make run-original        # Test original
  make map                 # View memory map
  make labels              # View labels
  make listing             # View listing
  make check               # Verify tools
  make help                # Show all targets

Method 3: Manual (Learning)
----------------------------
Commands:
  ca65 -t c16 -g -l build/main.lst -o build/main.o src/main.s
  ld65 -t c16 -o dorks_dilemma.prg -Ln build/labels.txt build/main.o
  xplus4 -autostart dorks_dilemma.prg

COMPATIBILITY NOTES
================================================================================

PlatformIO Unusual Usage
-------------------------
This project uses PlatformIO in a non-standard way:
• Target is 6502/C16, not a microcontroller
• Uses cc65 toolchain, not native PlatformIO tools
• "Upload" means launching emulator, not flashing hardware
• Custom build script (scripts/build_6502.py) handles assembly

This Works Because
------------------
✓ PlatformIO allows custom build scripts
✓ Uses 'native' platform as base
✓ Overrides default build process
✓ Integrates external tools (ca65, ld65, VICE)

Benefits
--------
✓ Full VSCode IDE integration
✓ Task runner and build automation
✓ Debug configuration management
✓ Extension ecosystem access
✓ Familiar workflow for PlatformIO users
